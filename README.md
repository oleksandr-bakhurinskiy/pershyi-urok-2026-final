# «Перший урок» — стенд на Android через GitHub Pages

Зберігається той самий HTML, дизайн 9:16, портрети, уроки, відео, факти, заставка та підтримка. На Android відкривається вебадреса. Встановлювати Node.js або запускати CMD-файли на стенді не потрібно.

## Опублікувати

1. Створіть у GitHub репозиторій, наприклад `pershyi-urok-kiosk`, з основною гілкою `main`. На тарифі GitHub Free для Pages потрібен публічний репозиторій.
2. Розпакуйте архів. Завантажте **вміст папки** `github-pages` у корінь репозиторію: `site`, `tools`, `.github`, `.gitignore`, `telegram-worker` і цей README. ZIP-файл у репозиторій завантажувати не потрібно. Перевірте, що `.github/workflows/pages.yml` також завантажився. Зручно зробити це через GitHub Desktop або git; у вебінтерфейсі приховані папки інколи доводиться додати окремо.
3. Відкрийте `Settings → Pages → Build and deployment → Source → GitHub Actions`.
4. Відкрийте `Actions → Publish kiosk → Run workflow → main`. Дочекайтеся зеленого результату.
5. Посилання буде в `Settings → Pages → Visit site`. Звичайний вигляд: `https://ВАШ_АКАУНТ.github.io/pershyi-urok-kiosk/`. Це приклад адреси, а не вже опублікований сайт.

Після наступних змін у `main` публікація запускається автоматично. Відвідувачам GitHub-акаунт не потрібен. Публікується лише папка `site`; службова частина Telegram у сайт не входить. Репозиторій та сайт містять публічні матеріали — жодних токенів або приватних chat_id тут немає.

## Щодня на Android

1. Під’єднайте стенд до інтернету та живлення.
2. Відкрийте адресу сайту в актуальному Chrome. Увімкніть вертикальну орієнтацію, вимкніть автоматичний поворот, якщо пристрій повертає екран.
3. Натисніть **⛶** угорі — сайт запросить повний екран. Якщо Android дозволить, він також утримуватиме екран увімкненим. Перевірте системний таймер вимкнення екрана.
4. Після 60 секунд бездіяльності вмикається заставка. Під час відтворення відео вона не перекриває плеєр. Дотик повертає до фіналістів.
5. Для налаштувань утримуйте логотип 3 секунди. На комп’ютері також працює Ctrl+Shift+S.

Можна додати ярлик сайту на головний екран через меню Chrome. Це ярлик, а не окремий APK. Автоматичне відкриття після увімкнення Android та блокування виходу з браузера налаштовуються окремо в пристрої або в кіоск-браузері; сам HTML цього не робить.

Після перезавантаження пристрою знову відкрийте сайт і натисніть ⛶. Це онлайн-версія: для першого відкриття, YouTube, оновлень і Telegram потрібен інтернет. Відкритий інтерфейс збереже поточні дані при короткому розриві; автономний запуск після перезавантаження не реалізований.

Підтримуються JPG, PNG, WebP та AVIF. Порядок — за назвою: `001.jpg`, `002.jpg` тощо. Рекомендовано фото до 1800–2000 пікселів по довгій стороні, приблизно до 1 МБ кожне. Максимум 120 фото події та 30 особистих фото кожного фіналіста.

Після завантаження й успішної публікації GitHub сам створить список фото. Стенд перевіряє цей список кожні 30 секунд. Публікація GitHub та кешування можуть додати затримку. Відкрите гостем фото зберігається, якщо воно залишилося в новому списку. На заставці чергуються портрет фіналіста та фото події. Поки фото події не додані, заставка показує портрети.

Старі папки Google Drive залишаються архівом, але **ця збірка не читає їх автоматично**. Автоматичне отримання з Drive потребуватиме додаткового підключення.

## Факти

Наявна таблиця зберігається:

https://docs.google.com/spreadsheets/d/1IRrbpF9_OXTBME1sM7Rc95l_zpUlL9j1uyS-zPol6wo/edit

Редагуйте аркуш «Факти», як раніше: число, підпис, текст, порядок та «Показувати». Аркуш для стенда має залишатися опублікованим як CSV. Його адресу вже вказано в `site/kiosk-config.js`. Стенд читає CSV напряму раз на хвилину. При помилці або недоступності джерела залишаються попередні факти; останній успішний список також зберігається у браузері.

Браузерне читання опублікованої Google-таблиці залежить від доступності Google та дозволу на запити з іншого сайту. Жива перевірка після публікації ще потрібна. Якщо Google блокує такий запит, CSV можна віддавати з адреси на тому самому сайті або через окрему серверну функцію, змінивши `factsCsvUrl`.

## Telegram — окреме підключення

GitHub Pages роздає HTML і JavaScript, але не запускає сервер бота. У цій збірці Telegram **за замовчуванням у деморежимі**: натискання нікому нічого не надсилає.

У `telegram-worker` є підготовлена функція для Cloudflare Workers. Вона зберігає токен на сервері, перевіряє код стенда та обмежує відправки. Вона ще не розгорнута і не підключена до живого бота. Наявного бота `@PershyiUrokSupport2026Bot` можна використати, створювати іншого не потрібно.

Технічне підключення з комп’ютера адміністратора:

1. Увійдіть у Cloudflare. Встановіть Node.js на **комп’ютері адміністратора**, відкрийте термінал у `telegram-worker` та виконайте `npx wrangler login`. На Android нічого з цього встановлювати не потрібно.
2. У `wrangler.toml` замініть `ALLOWED_ORIGIN` на адресу вашого GitHub-акаунта без шляху репозиторію: `https://ВАШ_АКАУНТ.github.io`.
3. Через `npx wrangler secret put НАЗВА` по черзі збережіть:
   - `TELEGRAM_BOT_TOKEN` — токен від BotFather;
   - `KIOSK_DEVICE_KEY` — випадковий код із щонайменше 24 символів;
   - `KIOSK_TEST_CHAT_ID` — приватний chat_id тестового отримувача;
   - `KIOSK_TEST_STICKER_ID` — Telegram `file_id` тестової наліпки.
4. Тестовий отримувач спочатку відкриває бота, натискає Start і надсилає одну наліпку. Для отримання chat_id та file_id можна використати локальний режим читання `--inspect-setup` зі старого серверного модуля. Не вставляйте токен в URL на публічних сайтах, у HTML або в репозиторій. Новий Worker не отримує вхідні повідомлення і не змінює webhook; ідентифікатори потрібно налаштувати окремо.
5. Виконайте `npx wrangler deploy`. Запишіть видану HTTPS-адресу функції у `site/kiosk-config.js`, поле `supportApi`, без кінцевого `/api/support`. Опублікуйте зміну в GitHub.
6. На Android утримуйте логотип 3 секунди, введіть **код стенда** та натисніть «Підключити». Код зберігається тільки в цьому браузері. Токен Telegram на Android не вводять.
7. Надішліть одну тестову наліпку. У тестовому режимі підтримка з будь-якої картки йде лише в тестовий чат.

Для фіналістів збережіть серверні секрети `KIOSK_RECIPIENTS_JSON` та `KIOSK_STICKERS_JSON`. Приклад структури з умовними значеннями:

```json
{"vodopian":{"chatId":123456789,"optedIn":true}}
```

```json
{"heart":"file_id_1","clap":"file_id_2","spark":"file_id_3","rocket":"file_id_4","flower":"file_id_5","luck":"file_id_6"}
```

Кожен фіналіст має сам почати чат із ботом; зіставлення приватного chat_id з людиною перевіряється організатором. Для однієї наліпки всі шість ключів можна зіставити з тим самим file_id. Після перевірки видаліть секрети `KIOSK_TEST_CHAT_ID` і `KIOSK_TEST_STICKER_ID`, щоб перейти на фіналістів. Оновіть сторінку стенда.

Ліміт: одна наліпка кожному фіналісту до повернення на заставку. Перезавантаження вкладки та повторне відкриття картки цей сеанс не скидають. Ліміт додатково зберігається на сервері, а повторний запит з тим самим request_id не створює нової відправки. При невідомому результаті від Telegram повторне надсилання в цьому сеансі блокується. Новий сеанс починається при показі заставки. Є додаткова пауза 30 секунд між відправками одному Telegram-чату.

## Перевірка перед подією

Перевірте на самому Android-стенді: повний екран, гортання, довгі теми уроків, YouTube зі звуком, нове фото в галереї та на заставці, новий факт із таблиці. Telegram спочатку перевірте на тестовій людині: одна успішна відправка, блок повтору, нова відправка після заставки.

Код перевіряється локально без справжніх відправок. Публікація GitHub, доступ до живої Google-таблиці, YouTube та доставка Telegram мають бути перевірені після розгортання.
